## 3. 직접 써보기

### 프로젝트 선정

 이전에 진행했던 공모전에서 개발했던 ‘걸음 수 측정 어플리케이션’ 프로젝트로 정했다.

 이번 과제의 개인적인 목표가 ‘새로운 코드 이해하기’가 아니라 ‘클로드 사용해보기’였기 때문에 코드와 기능에 대한 이해도가 충분한 프로젝트로 선정했다.

### 미완성 코드 찾기

 적은 시간 내에 빠르게 회의하고 개발한 코드기 때문에, 파일만 만들어 놓았다거나 프론트 코드와 연결 안 된 백엔드 코드들이 여럿 있을 거 같았다.

### 기능 추가

여러 미완성 부분 중, 프론트와 백 모두를 건드릴 수 있는 출석 체크 기능을 구현했다.

1. plan mode

처음엔 무턱대고 기능 구현 요구와 코드 작성 말고 계획부터 알려달라고 요청했다.

그랬더니 클로드가 알아서 plan mode로 변경 후 작업을 추천해줬고, 다시 plan mode가 있었음을 인지하고 작업을 진행했다.

2.  기능

앱에서 하루에 한 번 “출석체크” 버튼을 눌러 출석을 기록하고, 연속 출석일수(스트릭)을 확인한다.

추가로 이번 달 출석 현황을 캘린더를 통해 확인할 수 있게 하는 기능을 넣었다.

## 4. 다음 세션 공유거리 준비

### **신기했던 것**

1. 정확한 디자인, 기능 추천
    
    디자인이나 UI를 고민해보지 않고 그냥 위의 기능을 추가해달라고 기능 설명만 했다.
    
    사실 내가 놓치고 전혀 고려하지 못 한 부분을 세세히 후보 제시와 함께 짚어줘서 명확한 기능 구현을 할 수 있었다.
    
    반대로 이렇게 놓친 부분을 기억하고, 다음 개발에는 더 명확한 요청을 해야겠다는 생각을 했다.
    

2.  프론트 구현 과정에서 로그인 기능이 문제가 있었는데, 클로드가 알아서 그 흐름을 따라가며 로그인 기능(사전에 필요한 기능)까지 알아서 수정해주는 점이 신기했다.

### 이상했던 것 (질문)

처음 md파일을 만들고 프론트, 백 코드를 수정하다보니 md파일에 대한 의문이 생겼다.

md파일을 만드는 목적은 내가 전체적인 코드의 흐름을 이해하는 것도 있지만,
클로드에서 새로운 세션을 열었을 때 빠르게 작업흐름을 이해시키는 것이 주된 목적이라고 이해했다.

그렇다면 프론트/백/기타 코드 별로 md파일을 따로 만들고 시작하는 것이 더 유리한 게 아닐까? 하는 의문이 들었다.

아직 더 복잡한 코드 수정이나 기능 추가를 해보지 않아서 체감은 하지 못 했지만, 어떤 식으로 진행하는 게 더 효율적인지에 대한 고민이 생겼다.
