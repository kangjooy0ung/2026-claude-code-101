## 3. 커스텀 Slash Command + Hook

**먼저, 왜 훅이 필요해졌나 (2번의 연장선)**

커밋 단계에서 실험을 하나 했다. `"커밋 진행해줘"`라고만 지시하고 브랜치 얘기는 일부러 안 했다.
→ 로컬 Claude는 **현재 브랜치가 main임을 인지하고도 main에 직접 커밋했다**(`71aac5c`). 근거로 든 것은 "이 프로젝트의 이력이 main 직접 방식이고 사용자가 명시적으로 요청했다"였다. CLAUDE.md 규칙 언급은 없었다.

이어서 열린 탐침을 하나 더 던졌다. 관찰 포인트를 **미리 정해두고**(사후 각색 방지) `"규칙에 맞는지 검토해줘"`라고만 요청했다.
→ Claude는 main 직접 커밋을 관행 위반으로 스스로 짚어냈다. 그런데 **근거가 git 이력이었지 문서 규칙이 아니었다.** 문서에 규칙이 없었으니 당연한 결과였다(2번 참조).

교정: main을 `origin/main`으로 되돌리고 커밋을 `lock-analytics-endpoints` 브랜치로 옮긴 뒤 PR로 머지했다. 규칙 복원 커밋(`0fded45`)에서 로컬 Claude는 "정확한 원문이 없어 재작성했다"고 정직하게 명시했다.

**결론: 문서에 적힌 규칙은 advisory다. 강제하려면 실행 레이어가 필요하다.** 그래서 훅을 만들었다.

**만든 커맨드 (`.claude/commands/commit.md`):**
이미 존재하던 커맨드라 새로 만들기 전에 내용부터 확인했다. frontmatter의 `allowed-tools: Bash(git:*)`로 도구를 제한하고, 본문에서 `` !`git status` ``·`` !`git diff --staged` `` 문법으로 셸 출력을 컨텍스트에 넣은 뒤 Conventional Commits 형식으로 커밋시키는 헬퍼였다.
**문제: 브랜치 얘기가 한 줄도 없었다.** main에서 `/commit`을 치면 그대로 main에 커밋된다. 그래서 "커밋 전 브랜치 확인, main이면 커밋하지 말고 브랜치 생성을 먼저 제안" 지시를 추가했다.

**만든 Hook (`.claude/hooks/block_main_commit.py` + `.claude/settings.json`):**
`PreToolUse` 이벤트, matcher는 `Bash`. stdin으로 들어온 훅 페이로드에서 실행될 명령을 꺼내, **실제 `git commit` 실행인지** 판별한다. 문자열에 "commit"이 들어있는지로 보지 않고 `&&`·`||`·`;`·`|` 등 셸 연산자로 명령을 세그먼트 단위로 잘라 판별했다(우회 방지). main이면 exit 2 + 한국어 stderr로 차단 사유와 브랜치 생성 제안을 돌려준다.

**설계 결정 3개와 근거:**

| 결정 | 선택 | 근거 |
|---|---|---|
| 예외 발생 시 동작 | **절충** — 커밋으로 판별된 뒤의 예외만 차단, 판별 이전 예외는 통과 | 매처가 `Bash` 전체라 fail-closed면 모든 셸 명령이 막혀 세션이 마비된다. 폭발 반경을 커밋으로 좁혔다. |
| 설정 파일 위치 | **`.claude/settings.json`** (커밋되는 쪽) | 이번 주 결론이 "규칙은 커밋되어야 존재한다"인데 로컬 전용 파일에 넣으면 자기모순이다. |
| 차단 범위 | **main만** (master 제외) | 이 저장소에 master는 존재하지 않는다. 존재하지 않는 브랜치를 막는 규칙은 **문서에 없는 규칙을 강제하는 역방향 불일치**를 만든다. |

**"조용한 죽음" 대책:** fail-open으로 통과시키는 모든 예외는 `hook_errors.log`에 시각·에러 내용을 남기고 stderr에도 경고를 출력한다. 훅이 조용히 죽어서 "요즘 커밋 잘 되네"로 보이는 상황이 곧 이번 주에 겪은 "규칙이 조용히 유실된" 사건의 재판이기 때문이다. 단위 테스트용 샘플 JSON 3개도 파일로 저장해 언제든 재실행할 수 있게 했다.

**어떻게 연동했나:** `/commit` 실행 → Claude가 Bash 도구로 `git commit` 호출 시도 → PreToolUse 훅이 그 앞에서 가로채 판별 → 차단이면 stderr가 Claude에게 피드백으로 전달된다. 즉 **커맨드는 편의, 훅은 강제**로 관심사를 분리했다.

**검증 결과와 한계 (정직하게):**
- 단위 테스트 11/11 통과 — (a) main에서 `git commit` → exit 2 (b) 다른 브랜치 → exit 0 (c) `git status` → exit 0, 오탐/미탐 8케이스 전부 통과. fail-open 경로(깨진 JSON → 통과 + 로그 + 한글 안 깨짐)도 별도 확인.
- **라이브 검증은 미완이다.** 설정은 세션 시작 시 로드되므로 Claude Code 재시작 후에 실제 차단을 확인해야 하는데, 이번 주 범위 안에서 거기까지 가지 못했다. 커밋: `d871245`, PR: 
https://github.com/yenachang924/popketmon-server/pull/7
- **범위의 한계**: 이 훅이 잡는 것은 `git commit`뿐이다. `git merge`·`rebase`·`cherry-pick`·`push origin main`은 안 잡는다. 특히 **`git pull`은 내부적으로 fetch + merge라 main을 바꾸는데도 명령 문자열이 "pull"이라 어떤 확장으로도 안 걸린다.**
  → 훅은 실행되는 명령의 **겉면**만 본다. 그래서 이건 "main 변경 원천 봉쇄"가 아니라 **"의도적인 main 직접 작업을 눈에 띄게 만드는 장치"**다. 범위를 넓히는 것보다 한계를 정확히 아는 쪽을 택했다.

## 5. 회고

**겪은 삽질 — 인코딩 3연타**

1. **한글 grep 헛방** — CLAUDE.md에서 규칙을 찾는데 한글 검색이 아무것도 못 잡았다. 인코딩 문제일 수 있어 영어 `main`으로 재검색해 음성 결과 자체를 검증했다. → **"없다"는 결과도 검증 대상이다.**
2. **`commit.md` 화면 깨짐** — `type`으로 열었더니 한글이 전부 깨져 나왔다. 파일이 깨진 건지 화면이 깨진 건지 모르는 상태에서 관찰 포인트를 정하고("인코딩을 지정해 읽으면 복원되는가") `Get-Content -Encoding UTF8`로 확인 → **파일은 멀쩡했고 콘솔 해석이 문제였다.**
3. **전역 설정 파일 손상** — 훅 테스트용 더미 변경을 만들려고 `echo "" >> .claude/settings.json`을 실행했는데, **새로 연 PowerShell 창이 홈 디렉토리였다.** 프로젝트 파일이 아니라 `C:\Users\yenac\.claude\settings.json`(전역 설정)이 수정됐고, PowerShell 5.1의 `>>`가 UTF-8 파일에 UTF-16 CRLF(`0D 00 0A 00`)를 덧붙여 JSON 파서가 파일 전체를 거부했다. Claude Code가 "Invalid or malformed JSON"을 뱉었다.
   → 이번 주에 반복해서 나온 원리("PowerShell 창의 상태는 열린 순간 고정된다")가 인코딩 사고와 겹쳐 재등장한 사례. 그리고 **테스트 대상으로 하필 훅 설정 파일을 고른 것 자체가 설계 미스**였다 — 망가지면 테스트 자체가 불가능해지는 파일이었다.

**워크플로우가 어떻게 바뀌었나**

- **문서 규칙 → 실행 강제.** 1주차에는 CLAUDE.md에 규칙을 적는 것이 대응이었다. 2주차에는 그게 안 지켜지고 심지어 유실도 추적 불가능하다는 걸 겪었고, 훅이라는 실행 레이어를 붙였다. 문서는 해석되지만 훅은 실행된다.
- **탐침 전에 관찰 포인트를 먼저 선언한다.** 결과를 보고 나서 "이걸 보려던 거였다"고 말하는 사후 각색을 막기 위해서다. 이번 주 열린 탐침과 인코딩 진단 모두 이 방식으로 했다.
- **음성 결과도 검증한다.** grep이 아무것도 못 찾았을 때 "없구나"로 끝내지 않는다.
- **코치(나 자신 포함)의 해석도 검증 대상.** 이번 주에 두 번, 그럴듯한 해석이 검증으로 뒤집혔다. 뒤집힌 과정 자체를 기록으로 남겼다.

**다음에도 또 쓸 세팅 1가지**

**PreToolUse 훅.** 이유는 훅이 완벽해서가 아니라(3번의 한계 참조), **"내가 지키고 싶은 규칙"을 문서가 아닌 실행 가능한 형태로 옮기는 연습**이었기 때문이다. 이번 주에 잃은 74명의 데이터는 "위험을 문서에 적어두는 것"과 "위험을 막는 장치를 거는 것" 사이의 거리를 정확히 알려준 비용이었다.
