| **2. 문제** | 응급 상황에서 가족의 혈액형·복용 약·진단 기록을 모른다(종이·기억에 흩어져 있음). 멀리 사는 부모님은 매일 전화하기 부담스러워 안부 확인이 어렵고, 컨디션이 서서히 나빠져도 본인도 가족도 놓친다. |
| **3. 해결책** | ①비상 정보 금고에 혈액형·약·보험 위치를 모아 응급 시 **한 화면에 즉시 제시** ②버튼 하나 **안전 체크인** + 미체크 시 가족 알림 ③매일 컨디션을 수치화해 **월간·분기 추세**로 이상 흐름을 조기 포착 |
| **4. 왜 지금** | 고령화·1인 가구·비대면 돌봄 수요 증가. 정부 '나의건강기록'이 개인 조회는 열었지만 **가족 단위·안전 확인은 공백**. AI로 혼자서도 6주 안에 풀스택 MVP를 낼 수 있음. |
| **5. 사용자** | 주 사용자: 20~40대 자녀 + 60~70대 부모님, 서로 건강 정보를 공유하려는 부부. 확장: 1인 개인 건강 금고 모드, 만성·희귀질환자 커뮤니티 그룹. (규모: 가설 — 시니어 부모를 둔 국내 가구 수백만) |
| **6. 대안·경쟁** | '나의건강기록'(본인 조회만), 골든케어·팸핏(복약 알림·건강 습관 중심). 차별점: **가족 공동 관리 + 안전 체크인 + 응급 즉시 UX + 비상 정보 금고**를 하나로 묶음. |
| **7. 제품** | 핵심 3기능: ①비상 정보 금고 ②안전 체크인 + 미체크 알림 ③컨디션 추세 차트. **MVP** = 가족 그룹·구성원 프로필·비상정보(필수 3종 먼저)·매일 체크인·미체크 알림·병원 기록·솔로 모드. |
| **8. 지속 방법** | 무료(가족 1그룹·기록 20건) → 유료(기록 무제한·컨디션·건강수치 추세 차트·PDF 내보내기·알림 시간 커스텀). 매일 여는 체크인 앱이 되면 월 구독 전환. |
| **9. 나(팀)** | (가설) 가족 돌봄의 불편을 직접 겪어 문제를 잘 안다. 실시간 상태 동기화·알림 처리 백엔드 경험이 있음. |
| **10. 6주 계획** | **3주**: 가족 그룹·구성원 프로필·비상 정보 금고 / **4주**: 매일 체크인·미체크 알림 / **5주**: 컨디션 월간·분기 추세 차트·솔로 모드 / **6주**: UX 다듬기·배포·1분 피칭 |

> ⚠️ 법적 유의(초안): 건강 정보는 개인정보보호법상 민감정보 → 가입 시 별도 동의. 컨디션 차트는 "이번 달 컨디션이 낮아졌어요" 수준으로 표현하고 의료적 판단("이상 징후") 표현은 피한다. 데이터는 병원 연동이 아닌 **본인 직접 입력** 구조를 사용한다.

## 🔒 보안·프라이버시 (민감정보 신뢰 설계)

의료·비상 정보는 민감정보라 **"안전하다는 믿음"이 곧 사용 동기**다. 보안 자체를 차별점으로 가져간다.

- **저장 최소화**: 계좌번호·증권번호 원본이 아닌 **"어느 은행·어디에 있다"는 위치 정보만** 저장 → 유출돼도 피해 최소화.
- **암호화**: 전송 구간 TLS + 저장 시 민감 필드(혈액형·약·보험 등) **필드 단위 암호화(at-rest)**. 서버 관리자도 평문을 못 봄을 지향.
- **추가 잠금**: 비상 정보 금고 진입에 **PIN·생체인증** 옵션. 앱 잠금과 별도 2차 관문.
- **접근 통제**: 가족 그룹 단위 권한 — **그룹 구성원만** 해당 가족 정보 열람. 그룹 밖은 원천 차단.
- **감사 로그**: 비상 정보를 **누가·언제 열람/수정**했는지 기록 → 가족 간 신뢰와 오·남용 추적.
- **동의·투명성**: 온보딩에서 "가족 외 누구도 접근 불가" 명시, 민감정보 처리 별도 동의, 언제든 **전체 삭제(권리 행사)** 제공.

> MVP 우선순위: TLS·필드 암호화·그룹 권한(필수) → PIN 잠금·감사 로그(2차). 완벽한 보안보다 **"위치만 저장·가족만 접근"이라는 원칙을 온보딩에서 납득시키는 것**이 초기 신뢰의 핵심.
