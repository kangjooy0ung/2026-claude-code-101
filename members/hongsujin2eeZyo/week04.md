# 몽로그(Mong-log) 주간 개발 로그

## 1. 이번 주 한 일

### 데이터 개선

- 꿈 사전 키워드 개수 늘림

### 버그 수정

- **월간 리포트 악몽 카운트 오류**
  - 원인: "악몽"이라는 키워드 태그가 붙은 꿈만 카운팅되고 있었음
  - 해결: 수면유도 영상 추천 기준(감정이 부정적인 꿈)과 동일하게, 감정이 부정적이면 악몽으로 카운트되도록 변경

- **인물관계 네트워크에 장소가 표시되는 오류**
  - 원인: 해시태그에서 그대로 데이터를 가져오다 보니 인물이 아닌 장소도 인물관계도에 함께 표시됨
  - 논의: 해시태그 입력 폼에서 인물만 넣게 제한할지, 입력 후 필터링해서 구분할지 클로드와 상담
    - 한국어 특성상 이름과 장소를 구분하기 어렵다는 답변 (예: "바다"처럼 이름으로도 쓰이는 지명)
  - 결론: 입력 단계에서 태그 칸을 분리하는 방향으로 결정

- **로그인/회원가입 탭 전환 시 입력값 유지 오류**
  - 원인: 단순하게 만들기 위해 의도적으로 넣은 동작이었음 (클로드 확인)
  - 사용자 입장에서는 오류처럼 느껴져서, 탭 전환 시 입력값이 초기화되도록 수정

### UI/UX 개선

- 기분 상태 체크, 페이지 전환 등 디테일 수정
- 사용자 흐름을 따라가며 불필요한 요소 제거 (비밀번호 찾기, 회원가입 구글 버튼)
- 미구현 상태였던 로그인 상태 유지 기능 구현

### 회원가입 플로우

- 회원가입 테스트 중 이메일 인증 한도 초과 발생 → 테스트 불편으로 이메일 인증 옵션 제거
  - 원인 분석: 회원가입 기능을 요청할 때 조건을 명확히 명시하지 않고 "이메일 사용하고 이름도 추가해줘" 정도로만 요청하다 보니, 클로드가 스스로 판단해서 생긴 소통 오류로 추정
  - 교훈: 바로 구현을 요청하기보다, 대화형으로 요구사항을 충분히 정리한 뒤 개발을 진행하는 게 장기적으로 더 효율적이라고 판단

- **비로그인 유저 플로우 구현**
  - 목록/패턴/월간분석 기능은 비로그인 시 접근 제한
  - 사이트 최초 접속 시 유저 ID를 부여해 익명 유저로 꿈 기록 가능
  - 이후 회원가입 시 새 유저를 생성하지 않고 기존 익명 유저의 이메일/비밀번호만 업데이트하는 방식으로 구현
  - → 신규 유저가 회원가입 이전에 기록한 꿈 데이터가 유실되지 않도록 처리

### 테스트 중 발견한 이슈

- 질문: "구글 계정 로그인도 이 방식이 적용되나? (꿈 기록 → 분석 → 새 구글 계정 로그인 → 이전 꿈 기록 조회 가능?)"
- 발견: 이전에 "회원가입 탭에서 구글 버튼 빼줘"라고 요청했을 때, `handleOAuth`를 단순화하며 익명 계정과 구글 계정을 연결하는 `linkIdentity` 로직이 함께 삭제되어 있었음
- 교훈: 처음 요청 시 "구글 로그인"과 "회원가입"을 각각 더 구체적으로 명시했다면 클로드가 관련 오류를 스스로 찾아 해결했을 가능성이 있음 → 프롬프트를 더 자세히 쓰는 습관 필요
